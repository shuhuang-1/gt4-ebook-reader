# GT4 电子书阅读器

一个为**华为 WATCH GT 4** 圆形手表打造的本地电子书阅读器，基于 HarmonyOS **Lite Wearable**（JS + FA 模型）开发。

> **English**: A local ebook reader for Huawei WATCH GT 4 (466×466 round screen), built on HarmonyOS Lite Wearable (JS + FA model).

---

## ✨ 功能特性

| 功能 | 状态 | 说明 |
|---|---|---|
| 书架（卡片式） | ✅ | 显示每本书的阅读进度与"看到 N/M 章" |
| 目录页（卡片式） | ✅ | 分页加载，一次 20 章，滑到底自动追加 |
| 阅读页 | ✅ | 无限滚动加载，保留上文可回看 |
| 进度记忆 | ✅ | 每本书独立记录，点书直达上次位置 |
| 二级菜单 | ✅ | 单击屏幕弹出，半透明覆盖在正文之上 |
| 时间 / 电量显示 | ✅ | 菜单顶部实时显示 |
| 屏幕常亮开关 | ✅ | 点击灯泡图标切换，带 1 秒提示 |
| 阅读进度显示 | ✅ | 已读章数 / 总章数 |
| 字号 / 行距调节 | ⏳ | 待实现 |
| 书签 | ⏳ | 图标占位，功能待实现 |
| 手机导入书籍 | ⏳ | 入口已预留，通道待打通 |

### 二级菜单效果

```
21:37   72%                    ← 时间 + 电量
←    第1章 示例章节      ⋯     ← 返回 / 章节名 / 更多
                              
（正文透出区域，点击关闭菜单）
                              
☀     1 / 25             ⚑     ← 常亮 / 进度 / 书签
      阅读进度
```

菜单通过 `margin-top: -466px` **透明覆盖**在正文之上（不是跳转到新界面），正文依然可见，滚动位置不丢失。

## 🚀 快速开始

### 环境要求

| 项 | 版本 |
|---|---|
| DevEco Studio | 4.1 |
| HarmonyOS SDK | API 9（compileSdk / compatibleSdk = 8） |
| 设备 | 华为 WATCH GT 4 (PNX-B19)，HarmonyOS 5.0.0 |
| 模型 | **Lite Wearable / LiteOS，JS + FA 模型** |

⚠️ **不支持 ArkTS / Stage 模型**。这是 Lite Wearable 的硬性限制。

### 构建步骤

1. 用 DevEco Studio 打开 `MyApplication2/` 工程
2. 配置签名（File → Project Structure → Signing Configs）
3. Build → Build Hap(s)/APP(s)
4. 通过华为运动健康 App 或 `hdc` 安装到手表

### 添加你自己的书

编辑 `entry/src/main/js/MainAbility/pages/index/books.js`：

```js
var CH = [];

CH.push({ title: '第1章 章节名', text: '正文内容。段落之间用反斜杠n表示换行。' });
CH.push({ title: '第2章 章节名', text: '第二章正文' });

export default [
    { name: '我的书', chapters: CH }
];

// 注：text 里的换行用 \n 表示（JS 字符串转义）
```

**数据契约**（安卓端导入也复用这个格式）：

```json
{
  "name": "书名",
  "chapters": [
    { "title": "第1章", "text": "正文\n换行" }
  ]
}
```

> 大部头小说请用 `mkvol.js` 自动分卷（见下方"分卷工具"）。

## 📁 项目结构

```
entry/src/main/js/MainAbility/pages/index/
├── index.hml        # 三页结构：书架 / 目录 / 阅读页
├── index.css        # 466×466 圆屏适配样式
├── index.js         # 全部业务逻辑
└── books.js         # 书籍数据（示例书，替换为你的书）
```

**核心参数**（在 `index.js` 顶部）：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `SEG_LEN` | 17 | 每行字数（17 × 27px = 459 < 466） |
| `PAGE_SEG` | 40 | 滑到底一次追加多少行 |
| `PREV_LINES` | 20 | 进页面预带多少行上文 |
| `MAX_LINES` | 160 | 累积上限，防止越滚越卡 |
| `TOC_PAGE` | 20 | 目录每次加载几章 |
| `LIGHT_TICK` | 3000 | 屏幕常亮维持间隔（ms） |

## ⚠️ 已知限制（重要）

这些是**真机实测**得出的结论，能帮你省下大量试错时间：

### 1. Lite Wearable 没有可用的文件写入通道

```
@system.file.writeText  →  fail 202（参数错误/不支持）
@system.file.readText   →  rawfile 三种 uri 全部失败
```

**结论**：无法在手表端接收外部导入的书籍文件。这是本项目最大的瓶颈，也是需要安卓端配合的根本原因。

### 2. rawfile 方案不可行

曾尝试把书数据放 `resources/rawfile/` 后运行时读取 —— **Lite 的 JS 读不到 rawfile**，方案作废。书数据必须编译进 JS。

### 3. 大体积书籍安装会崩

| 体积 | 结果 |
|---|---|
| ~118 KB（约 35000 字） | ✅ 可安装 |
| ~275 KB（约 91000 字） | ❌ 安装中黑屏、蓝牙断连 |

建议单卷控制在 **27 KB 以内**，超出请分卷或分册。

### 4. 屏幕常亮的真实能力边界

`brightness.setKeepScreenOn({ keepScreenOn: true })` + `setInterval` 周期调用可以保持亮屏，但：

- ✅ 能防**无操作超时息屏**
- ❌ 防不住**主动遮屏 / 落腕熄屏**（系统行为，第三方无法干预）

### 5. 预览器的坑

DevEco 预览器对 Lite Wearable **渲染不出 `<text>` 文字**，只能看布局（框的位置 / 大小 / 圆角）。**文字相关（字号 / 字数 / 颜色）必须装机验证。**

另外预览器存在**偏移 bug**，卡片在预览器里偏右属正常现象，以真机为准。

### 6. 其他平台的适配情况

| 平台 | 结论 |
|---|---|
| 红米 Watch 5 | ❌ 澎湃OS 与 HarmonyOS 包格式不互通，需完全重写 |
| 其他 466×466 鸿蒙手表 | 大概率可用，需验证 |

## 🛠 分卷工具

`mkvol.js` 把大部头 txt 自动切成多个 JS 卷，避免单文件过大：

```js
var VOL_CHARS = 8000;   // 每卷字数，装不上就调小（8000 → 6000）
```

配置好输入源后运行 `mkvol.bat`，会生成 `book1_vol1.js`、`book1_vol2.js` ... 并自动重写 `books.js`。

### 给安卓端开发者

如果你愿意做安卓配套 App，这是你需要知道的：

**数据格式**：与 `books.js` 完全一致

```json
{ "name": "书名", "chapters": [{ "title": "第1章", "text": "正文\n换行" }] }
```

**建议的技术路线**：华为 **HiWear P2P**（手机 → 手表，官方支持大文件传输）。
Lite Wearable **不支持**自研蓝牙传输，别在这上面浪费时间。

**可复用的调参结果**（都是真机试出来的，直接抄）：

```
每行字数 17（字号 27px）
一次追加行数 40
上文缓冲 20 行
累积上限 160 行
```

⚠️ 但请先读上面"已知限制 1"—— 手表端目前**没有可用的文件写入通道**，这是需要优先攻克的关卡。
